# v1.0.4.9 field diagnostics command inventory

用途：一次調查現場常見的「畫面數字看起來不一致」問題，避免只看單一畫面就猜原因。

本文件涵蓋：

- 資產管理總數、正式 / 草稿 / 下線排除口徑
- 開門檢查候選台數、平台分頁、系統分組、已巡檢 / 可巡檢 / 待補條件
- CMDB 資料品質異常分類
- CMDB 關聯覆蓋明細台數與 owner / port / notification 口徑
- 核心系統影響圖 / 拓撲實際畫出的主機台數
- 實際巡檢結果 collection 與資產主檔的對應狀態

安全規則：

- 指令只輸出數量、狀態、平台分類、欄位存在與 12 碼 hash。
- 不輸出真實 IP、主機名稱、系統名稱、人名、email、電話、asset id、system id、帳號、token 或 raw log。
- 請只貼回 `/tmp` 產生的 JSON 檔案內容。
- 不要貼 raw Mongo document、journalctl、systemctl status、完整畫面文字或未遮罩截圖。

```bash
    text = str(value or "").strip()
    if not text or text == "-":

    return hashlib.sha256(text.encode("utf-8", "ignore")).hexdigest()[:12]

    return str(value or "").strip()

            host.get("hostname"),
            host.get("ip"),
            host.get("apid"),
            host.get("group_name"),
            host.get("device_type"),
        ]
    )
    return any(needle in system_match_key(value) for value in values if value)


def public_host_key(host):

def safe_counter(values):
    return dict(sorted(Counter(values).items(), key=lambda item: (-item[1], str(item[0]))))
```

## 2. 回傳方式

請只回傳 `/tmp` 產生的 JSON 檔案內容：

```bash
cat "$OUT"
```

如果已離開原本 shell，找最新檔案：

```bash
ls -lt /tmp/webitgpt_field_diagnostics_*.json | head
cat /tmp/webitgpt_field_diagnostics_YYYYMMDDHHMMSS.json
```

## 3. 這份輸出要看哪裡

| 問題 | 看 JSON 欄位 | 判讀 |
|---|---|---|
| 資產總數為何對不上 | `asset_counts`、`asset_ui_metric_reconciliation` | `visible_total` 是未下線資產；`draft_like_total` 是人工待判斷；自動彙整不應和人工待判斷重複相加。 |
| 開門檢查為何不是全部資產 | `opening_scope.scope_summary` | 開門檢查只納入 `linux/windows/aix/as400`；端點、網路設備、VMware host 會被排除。 |
| Linux 分頁為何只有 15 台 | `opening_scope.opening_candidate_by_platform` | 平台分頁只看該平台，不等於所有資產。 |
| 某套系統為何只有部分主機 | `query_scope.matched_platform_counts` | 若同一套系統分散在 Linux、Windows、AS400，單一平台只會顯示其中一部分。 |
| 已納管但卡在待連線 | `inspection_results`、`opening_scope.missing_connection_by_platform` | 代表資產已進系統，但連線方式、帳號、port、防火牆或實際巡檢結果尚未完成。 |
| CMDB 品質說有異常 | `quality.cmdb.counts`、`quality.operations.summary` | 看是平台分類、缺連線方式、流程未結案、掃描/CMDB 不一致或必填欄位缺漏。 |
| 關聯覆蓋數量怪 | `relationship_coverage.summary`、`relationship_coverage.top_system_rows` | 看系統分組總數、正式/草稿、owner、port 與通知依據是否從完整 visible 資產口徑計算。 |
| 拓撲台數與資產主檔不同 | `dependency_topology.query_topology`、`dependency_topology.query_system_samples` | 看 dependency system 是否命中、host_refs 數量與實際 topology host_nodes 是否一致。 |

## 4. 不要再貼的資料

以下資料不需要，也不要貼回：

- 真實 IP、hostname、系統名稱、人名、部門、email、電話
- raw Mongo document
- journalctl / systemctl 原文
- access.log / error.log 原文
- token、API key、SSH 帳號、密碼
- 未遮罩截圖

如果這份 JSON 仍不足以定位問題，再由工程端追加第二份更窄範圍的去敏指令；不要先回傳原始資料。
