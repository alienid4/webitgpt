# 圖像化儀表板路線

## 原則

使用者閱讀順序採用：

圖 > 表 > 文字

主管頁優先用圖形回答「正常嗎、哪裡有風險、要先看哪裡」。表格和文字只作為下鑽明細。

## 第一階段：內建圖表

狀態：進行中

做法：

- 在 webitgpt 內建主管圖表。
- 使用現有 MongoDB 與服務摘要資料。
- 不新增 Grafana、Prometheus 或額外服務。
- 圖表先以 CSS 長條、圓環和趨勢卡呈現。

已納入：

- 資產狀態分布
- 平台分布
- 帳號風險圖
- 合規健康圓環
- 機房分布
- 環境分布

## 第二階段：Prometheus Metrics

狀態：待做

目標：

- 擴充 `/metrics`。
- 輸出主機數、開門檢查 WARN/FAIL、帳號風險、合規異常、L3 深度檢查結果。
- 讓外部監控可以收長期趨勢。

注意：

- 只輸出統計數字，不輸出敏感帳號、主機密碼、token、raw log。
- 不改變 webitgpt 的主操作流程。

## 第三階段：Grafana

狀態：待評估

定位：

- Grafana 只做圖表牆、長期趨勢和大螢幕展示。
- 不取代 webitgpt 的資產編輯、帳號處置、修補、rollback、白名單與權限管理。

前置條件：

- 第二階段 metrics 穩定。
- 確認部署主機資源與維運方式。
- 確認資料源採 Prometheus 或其他中介資料，不直接讓 Grafana 承擔核心業務邏輯。
