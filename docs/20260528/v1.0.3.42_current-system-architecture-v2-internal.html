淡金框：AI-ready

資料已整理成可交給 AI 判讀，但目前不代表 AI 已經實際下判斷。

深金框：AI 判斷

虛線橘框：Script 接手

API 或 AI 不可用時，以既有 Script 規則保底，避免巡檢中斷。

AI Judgement Model

判斷來源與 AI 視覺語意

採證來源

Shell / Script
curl、ss、nmap、nmon、SSH/WinRM、系統命令。負責取得事實與原始證據。
CMDB / Rule
資產欄位、owner、PAM、備份、個資、完整性/機密性/可用性分級。
API Key
外部或自動化系統以 token 呼叫 API，確認版本、Mongo、資料品質與服務狀態。
AI / LLM
讀取採證資料後做 L3 深度判讀、摘要、風險推論與建議。

核心原則

Shell 負責採證，AI 負責判讀。

AI 不應憑空猜測主機狀態；它應讀取 Shell、API、CMDB、NMON、log 所提供的證據，再產生判讀。

如果 AI provider、API Key 或預算不可用，系統應退回既有 Script 規則，頁面以「AI 不可用時規則接手」清楚標示。

可交給 AI 判讀 真正 AI 判斷 AI 不可用時規則接手
畫面位置 目前語意 視覺規則
/inspections L3 深度檢查 可由 AI 進行深度判讀，或在 AI 不可用時由 Script 保底。 真正 AI 結果用深金框；待判讀資料用淡金框；fallback 用橘色虛線。
/accounts、/reports、/nmon、/dependencies 多數是 AI-ready 資料整理，尚不等於 AI 已下判斷。 淡金框或 AI-ready badge，避免使用者誤認為已由 AI 產出。
/superadmin/ai、/superadmin/token-costs 設定與治理 AI key、tier、預算與 debug。 設定區可淡金框；實際 AI 判讀紀錄才深金框。

Data Flow

資料流與 MongoDB 現況

輸入資料

CMDB CSV/Excel、AP 帳號 CSV/Excel、nmap 掃描、NMON raw、SSH/WinRM 採集、人工維護欄位。

資料處理

欄位正規化、草稿區、驗證規則、差異報告、資料品質檢核、AI-ready 摘要。

輸出結果

資產清單、巡檢結果、效能月報、核心影響圖、CSV/Excel 匯出、API JSON、debug bundle。

資料類型 目前儲存 用途 未來方向
正式資產與草稿 MongoDB CMDB 匯入、draft review、資產管理與拓撲關聯。 可評估同步或搬遷到 MSSQL 作正式主資料庫。
掃描與巡檢結果 MongoDB nmap、巡檢、deep check、歷史結果查詢。 保留 Mongo 彈性；摘要可寫入 MSSQL 供治理報表。
NMON raw/sample MongoDB + 檔案匯入 效能月報、趨勢圖、EOS/容量摘要。 raw 留 Mongo/檔案，彙總指標可進 MSSQL。
AI token 與成本 MongoDB 預算控管、L1/L2/L3 key routing、debug。 正式稽核可進 MSSQL，保留交易與稽核欄位。
建議方向不是 Mongo 或 MSSQL 二選一，而是：Mongo 保留彈性採集/半結構資料，MSSQL 承接正式治理、稽核、權限與管理報表。

AI Key Routing

API Key、L1/L2/L3 與預算控制

L1 基礎檢查 Script-first
不需要 AI 或使用最低成本模型
L2 一般判讀 低成本 API Key
摘要、分類、欄位治理
L3 深度檢查 高階 API Key
深度推論、跨資料源關聯、風險建議

設定介面

/superadmin/ai 管理 provider、model、API Key、預設等級與 fallback。

成本監控

/superadmin/token-costs 追蹤 token、估算成本、月預算與超額策略。

超額策略

超過預算時停用高階 key、降級到 L2/L1，或切回 Script 規則。

API Key 不應出現在前端、版本庫、截圖或文件。文件只能描述欄位與流程，不放真實 key。

Offline Delivery

離線移植與版本發布流程

Full Offline Installer

用於新機或大版本移植，包含應用程式、wheelhouse、install script、必要文件與 checksum。

RHEL 9.6 必須避免混入 Rocky release/rpm，Podman/MongoDB 要有可診斷的前置檢查。

Patch Package

用於已部署主機的快速修補，保留備份與回滾路徑，檔名遵守「版本_功能」且版本在前。

使用者要執行的指令必須放在 docs/YYYYMMDD 文件中。

Current Gaps

目前風險與未完成項目

v1.0.3.42 尚未 Release

原因：221 測試主機暫時不可達，無法完成使用者要求的「221 先測後上 正式發布」。

RHEL 9.6 full installer 要再收斂

曾遇到 Rocky/RHEL RPM 混包、Podman 未裝導致 Mongo 不可用、bootstrap 連線失敗。

OpenAPI 尚未全覆蓋

/api/v1 已有基礎，但舊 API 回應格式與文件仍需漸進補齊，不能一次破壞前端相容性。

MSSQL migration design 尚未完成

公司規範偏好 MSSQL；webitgpt 目前 Mongo 適合採集與半結構資料，正式治理可規劃雙資料庫。

AI-ready 不等於 AI 已判斷

v1.0.3.42 已將可交給 AI 判讀的區塊改淡金框；真正 AI 判斷才用深金框。

大量匯入 UX 還可加強

CMDB 匯入失敗應用一眼看懂的摘要、錯誤列下載、欄位對照與進度回饋。

Operator Route Map

維運入口與判斷來源對照

路徑 用途 主要來源 AI 視覺語意
/hosts 資產管理、CMDB、草稿區、匯入匯出。 CSV/Excel、MongoDB、人工維護。 欄位治理可 AI-ready，資料本身不是 AI 判斷。
/accounts OS/AP 帳號盤點與異常摘要。 OS script、AP CSV/Excel、PAM/owner 規則。 可交給 AI 彙整風險，使用淡金框。
/inspections 今日巡檢、L1/L2/L3 深度檢查。 Script、runner、API、AI。 L3 真正 AI 判斷用深金框，fallback 明確標示。
/nmon 效能月報、NMON raw、EOS 與容量摘要。 NMON raw/sample、OS lifecycle rule。 摘要可 AI-ready；原始圖表仍是資料採證。
/dependencies 核心系統影響圖、三欄式關係、通知匯出。 CMDB、ss+nmap、人工/自動關係。 關係摘要可 AI-ready；圖上關係需保留來源。
/reports/post-install 安裝後驗證與 API Key 驗證說明。 curl script、API token、health/ready。 API 判斷與 Script 檢查分開顯示。
/superadmin/ai AI provider、key、model、fallback 設定。 環境變數 / 後端設定 / MongoDB。 設定區淡金框；不顯示真實 key。
/superadmin/token-costs token 使用量、成本、預算、tier routing。 AI usage log、模型價格、預算設定。 治理與成本摘要可 AI-ready。
