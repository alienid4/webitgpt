# v1.0.4.0 - relationship-coverage-system-key-fix

## Changes

- Fixed CMDB relationship coverage grouping so the system/group table uses `system_name`, `asset_name`, or `APID` as the system key.
- Stopped using the asset `group_name` field as a system grouping key. This prevents a shared asset group from being displayed as one oversized system, such as a virtualization platform row containing hundreds of unrelated assets.
- Ignored placeholder system names such as draft, unclassified, pending, `N/A`, and `-` when selecting a relationship grouping key.
- Added regression coverage to confirm rows with the same asset group but different asset/system names are not merged.

## Field Note

This patch does not insert or modify asset data. It only corrects how the CMDB relationship coverage page groups existing assets for reporting.
