# v1.0.3.44 - host-data-dir-permission-guard

Release date: 2026-05-29 10:05 +08:00

## Root Cause

Company-host testing showed:

```text
儲存失敗：[Errno 13] Permission denied: '/opt/webitgpt/data/hosts/...'
```

The host record save can succeed in MongoDB, but the app also tries to create or update `/opt/webitgpt/data/hosts/<asset_seq>/meta.json`. If the service account cannot write that directory, the UI reports a save failure.

## Changes

- Host directory and `meta.json` sync are now best-effort after MongoDB save.
- If directory sync fails, the host record remains saved and gets:
  - `host_dir_status=warning`
  - `host_dir_error=<permission error>`
  - `host_dir_checked_at=<timestamp>`
- Patch install fixes ownership for `/opt/webitgpt/data`, `/opt/webitgpt/logs`, and `/opt/webitgpt/backup` when `sysinfra:itagent` exists.

## Field Fix Command

```bash
sudo mkdir -p /opt/webitgpt/data/hosts /opt/webitgpt/data/hostnames /opt/webitgpt/data/archive /opt/webitgpt/logs /opt/webitgpt/backup
sudo chown -R sysinfra:itagent /opt/webitgpt/data /opt/webitgpt/logs /opt/webitgpt/backup
sudo chmod -R u+rwX,g+rwX /opt/webitgpt/data /opt/webitgpt/logs /opt/webitgpt/backup
sudo systemctl restart webitgpt
curl -fsS http://127.0.0.1:8002/health
```
