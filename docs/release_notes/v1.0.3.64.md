# v1.0.3.64 - Topology Hosts From Asset Master

## Purpose

Fix a field issue where an asset/system had more hosts in the asset master than the core impact topology showed.

## What Changed

- Core impact topology no longer relies only on `dependency_systems.host_refs`.
- When a system is selected, hosts are also backfilled from the asset master by matching the business system name.
- Host topology node ids now prefer `asset_seq`, then hostname, then IP, so asset-master rows remain stable even when hostname references are stale.
- Discovery-only rows remain excluded from becoming business systems, following v1.0.3.63 behavior.

## Verification

- `python -m compileall webapp`
- `python -m pytest -q`
- Deploy to 221 before release and verify:
  - `/health` returns `version=1.0.3.64`
  - `/health` returns `patch_id=topology-hosts-from-asset-master`
  - `/dependencies?view=core_impact` returns HTTP 200
  - A selected system with stale `host_refs` still shows hosts from the asset master
