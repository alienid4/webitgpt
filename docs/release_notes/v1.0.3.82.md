# v1.0.3.82 data-quality-stale-scan-reconcile

## 變更內容

- 資料品質報告讀取最近 `network_scan_reports` 前，會以目前 CMDB 主檔 IP 重新覆核。
- 若掃描報告中的 `scan_not_in_cmdb` IP 已存在於未退休資產，不再顯示為「掃描到但 CMDB 無」。
- 同一份資料品質報告會去除重複的舊掃描異常，避免同一 IP 被不同舊掃描報告重複計算。

## 解決問題

現場診斷顯示部分 `scan_not_in_cmdb` IP 已經能在 hosts 主檔找到，且多數為 active。這代表不是使用者資料缺漏，而是舊掃描報告殘留造成誤判。

```bash
pytest tests/test_cmdb_real_fields_and_scan_summary.py tests/test_asset_account_ui.py
```

## 注意

- 這版不會刪除舊掃描報告，只是在資料品質報告產生時做即時覆核。
- 真正不存在於 CMDB 主檔的掃描 IP 仍會保留為「掃描到但 CMDB 無」。
