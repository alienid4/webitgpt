# v1.0.3.43 - host-draft-save-error-guard

Release date: 2026-05-29 09:35 +08:00

## Changes

- Host create and draft edit save failures no longer return a generic Internal Server Error page.
- The host form keeps the submitted values and displays `儲存失敗：...` so the operator can correct the data.
- Server logs now include `host_new_submit failed` or `host_edit_submit failed` traceback for root-cause analysis.

## Why

Company-host testing found that completing draft host data could hit a 500 page. This hotfix prevents the white page and makes the failure actionable while preserving a server-side traceback.

## Validation Plan

- Run `python -m pytest -q`.
- On the target host, retry the failed draft save.
- If the save still fails, collect the traceback:

```bash
sudo journalctl -u webitgpt -n 200 --no-pager | egrep -A30 'host_edit_submit failed|host_new_submit failed|Traceback'
```
