# v1.0.3.43 主機草稿儲存錯誤現場排錯指令

用途：公司主機在「新增主機 / 草稿補資料 / 儲存資產」時，若畫面出現 `儲存失敗` 或曾出現 Internal Server Error，請使用本文件收集資訊。

版本：v1.0.3.43  
Patch：host-draft-save-error-guard  
日期：2026-05-29

## 1. 確認目前版本

```bash
curl -fsS http://127.0.0.1:8002/health
curl -fsS http://127.0.0.1:8002/ready
```

期待：`/health` 內應看到：

```text
"version":"1.0.3.43"
"patch_id":"host-draft-save-error-guard"
```

## 2. 收集主機新增 / 草稿儲存錯誤

```bash
sudo journalctl -u webitgpt -n 300 --no-pager | egrep -A40 'host_edit_submit failed|host_new_submit failed|Traceback|ValidationError|儲存失敗'
```

## 3. 收集最近 10 分鐘完整服務 log

```bash
sudo journalctl -u webitgpt --since "10 minutes ago" --no-pager
```

## 4. 若畫面仍可操作

請重做一次失敗動作，然後立刻執行：

```bash
sudo journalctl -u webitgpt -n 120 --no-pager
```

## 5. 回報時請提供

請回報以下資訊，敏感資料可遮蔽：

```text
1. /health 輸出版本與 patch_id
2. 畫面顯示的「儲存失敗：...」文字
3. journalctl 中 host_edit_submit failed 或 host_new_submit failed 後面的 Traceback
4. 當時是「新增主機」還是「草稿補資料後儲存」
```

## 6. 臨時回復方式

若 patch 後行為異常，可在解壓目錄執行：

```bash
cd /tmp/webitgpt_v1.0.3.43-patch-host-draft-save-error-guard_20260529093500
sudo bash ROLLBACK.sh /opt/webitgpt
curl -fsS http://127.0.0.1:8002/health
```
