# 掃描 / 盤點 / 採集狀態顯示 SKILL

## 適用範圍

凡是按鈕會觸發掃描、盤點、採集、巡檢、對帳或長時間背景檢查，都套用本規則。

## 固定規則

- 頁面初次開啟時，要預設顯示最近一次成功或失敗的結果。
- 使用者重新執行時，畫面要保留上次結果，只在上方或按鈕旁顯示「正在執行」狀態。
- 不可因為新任務尚未完成，就把結果表格、摘要、勾選清單清成空白。
- 狀態文字要說明大約多久、是否可重複點選、目前顯示的是上次結果。
- 新結果完成後，才替換成最新結果。
- 失敗時也要保留上次結果，並顯示本次失敗原因。

## UI 實作

- 表單使用 `data-submit-status`。
- 長時間表單加上 `data-preserve-results`，表示送出時保留既有結果區。
- `data-submit-message` 要明確寫「下方會先保留上次結果」。
- 後端 context 若沒有新結果，要讀取最近一次結果。

## 後端實作

- 掃描結果要寫入 Mongo 或檔案歷史，不只存在 memory。
- 最新結果查詢應提供 `latest_*` helper。
- POST 失敗時應回傳舊結果 + 錯誤訊息，而不是只有錯誤頁。
- 結果要記住使用者上次條件，例如 CIDR、機房、環境、掃描模式。

## 驗收

- 進頁面不用按任何按鈕，也看得到上次結果。
- 按開始掃描後，上次結果仍在畫面上。
- 失敗時，上次結果仍在畫面上，並能看到本次錯誤原因。
- 測試至少檢查模板有 `data-preserve-results` 與「上次掃描結果」文字。
