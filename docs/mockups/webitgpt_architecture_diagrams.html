資訊戰情室 / IT 巡檢系統架構圖

同一套系統可以有不同架構圖：給主管看整體、給維運看流程、給安裝人員看部署。

用途：讓主管一眼看懂誰使用、系統處理什麼、資料存哪裡、最後產生什麼結果。

功能模組架構圖

用途：說明系統有哪些功能，每個功能解決什麼問題。這張適合回答「這專案做了什麼」。

建議放功能說明

資產管理

管理主機、IP、OS、機房、環境、狀態，支援草稿與缺漏治理。

帳號盤點

看高權限、PAM、服務帳號、異常帳號，並保留盤點差異。

開門檢查

每天快速確認主機狀態，用小卡呈現重點，不讓維運淹沒在 raw data。

L3 深度檢查

針對單台主機做更深入診斷，提供證據、判斷、建議指令。

效能月報

以 NMON raw file 為主，整理月度趨勢、熱點主機與容量風險。

系統拓撲

顯示核心系統、關聯系統、主機/IP，輔助影響評估與維護通知。

系統管理

管理功能開關、權限、排程、日誌、例外清單與操作紀錄。

開發後台

保存文件、提交紀錄、debug bundle、AI 接手資料與版本資訊。

TWGCB / 合規

未來整理成規則庫、稽核報表與修補紀錄。

Housekeeping

清理 Mongo、NMON raw、log、暫存與舊報表，避免磁碟爆滿。

通知與簽核

把需要主管或負責人確認的事件整理成通知名單。

AI 輔助分析

不直接接 VM，改由去識別或內部 bundle 交給公司 GPT 分析。

離線部署與移植架構圖

用途：說明 221、224 與 Windows PC 各自負責什麼，避免誤以為離線主機還要下載套件。

給安裝與交付使用

Windows PC

  • 整理程式碼、文件、版本紀錄。
  • 準備安裝腳本與操作說明。
  • 不負責下載 Rocky/RHEL RPM。
  • 不打包 Mongo container image。

221 可上網建包機

  • 產生完整離線包。
  • 包含 RPM、Python wheels、Mongo image。
  • 包含 nmap、nmon、podman。
  • 產生 `INSTALL_ALL.sh`。
  • 檢查包內不可含測試資料與 log。

224 離線測試機

  • 不能上網下載任何套件。
  • 只解壓完整離線包。
  • 執行 `sudo bash INSTALL_ALL.sh`。
  • 安裝後檢查 health、ready、service。
  • 正式資料由 CMDB Excel/CSV 匯入。
一句話說法：Windows 負責整理，221 負責打完整離線包，224 只負責一鍵安裝，不再連外下載。

AI Debug Loop 架構圖

用途：說明公司 VM 不直接給 GPT 連線，而是由系統產生 debug bundle，再交給公司 GPT 分析。

給 AI 工具討論會
1

VM 上跑系統

問題發生在公司測試機或正式前環境。

2

產生 Debug Bundle

收集版本、設定摘要、log、狀態、磁碟、記憶體。

3

資料分流

公司 GPT 可保留內部資訊；外部 AI 必須遮蔽敏感資料。

4

AI 協助分析

判斷可能原因、建議修法、需要補哪些 log。

5

Codex 修正程式

把問題變成可追蹤修正，必要時補 regression test。

6

重新部署驗證

測試機驗證通過後，再進入 release 或 patch 流程。

角色負責事項限制
公司 GPT協助分析內部 debug bundle 與開發問題不直接連 VM，不直接改系統
Codex寫程式、修 bug、產測試、整理文件敏感資料需依場景遮蔽
工程師執行安裝、驗證畫面、判斷是否上線危險操作要人工確認
