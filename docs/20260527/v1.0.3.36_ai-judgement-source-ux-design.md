# v1.0.3.36 AI 判斷來源視覺規格

日期：2026-05-27  
版本：v1.0.3.36  
功能代號：ai-judgement-source-ux

## 核心原則

> Shell 負責採證，AI 負責判讀；AI 不可用時，Script 保底接手。

這是 webitgpt 後續 AI 化的核心設計原則。  
AI 不應取代 shell/script 的事實採集能力；AI 應用在跨資料來源的判讀、風險解釋、可能原因、影響範圍與下一步建議。

## 為什麼要做判斷來源標示

同一個檢查結果可能來自不同機制：

- Script 固定規則判斷
- API Key 正式 API 驗證
- AI 綜合判讀
- Script 採證 + AI 判讀
- AI 失敗後 Script 接手

如果 UI 沒標清楚，維運人員無法判斷結果的可信度、追查方向與限制。  
因此每個 L1/L2/L3 檢查、報表章節、卡片與結果列都應標示判斷來源。

## 判斷來源標準

| 判斷來源 | 語意 | UI 樣式 | 報表文字 |
|---|---|---|---|
| Script 判斷 | 本機 shell/script/rule-based 固定規則 | 灰框或一般框，`Script 判斷` badge | 由 Script 規則判斷 |
| API Key 驗證 | 使用 token/key 呼叫後端 API 驗證 | 綠色 accent，`API Key 驗證` badge | 由正式 API 權限驗證 |
| AI 判斷 | AI 根據證據做綜合判讀 | 金框，小 AI icon，`AI 判斷` badge | 由 AI 綜合判讀 |
| AI + Script | Script 採證，AI 解讀 | 金框，`AI + Script` badge | Shell 採證 + AI 判讀 |
| Script 接手 | AI timeout/error 後改用 script rule | 灰黃框，`Script 接手` badge | AI 不可用，已改由 Script 保底 |
| 證據不足 | 採證失敗或資料不足 | 紅框，`證據不足` badge | 無法判斷，需補採證 |

## L1 / L2 / L3 分流

| 等級 | 預設判斷 | 適合內容 | AI 可用時 | AI 不可用時 |
|---|---|---|---|---|
| L1 基礎檢查 | Script only | service up、port open、version match、disk threshold | 不一定需要 AI | Script 照常 |
| L2 一般判讀 | Script + 輕量 AI 可選 | 摘要、分類、欄位缺漏解釋、低風險建議 | 可用低成本模型 | Script rule 接手 |
| L3 深度檢查 | Script 採證 + AI 深度判讀 | CMDB、nmap、NMON、帳號、log、拓撲綜合判斷 | AI 優先 | Script 保底接手 |

## L3 深度檢查 UI 範例

```text
L3 深度檢查    [AI 判斷]
來源：Shell 採證 + AI 判讀
證據：CMDB、nmap、NMON、帳號盤點、服務狀態
信心：高
結論：疑似服務角色與 CMDB 登錄不一致，且近期效能指標有異常尖峰。
```

若 AI 失敗：

```text
L3 深度檢查    [Script 接手]
原因：AI API timeout，已改用本機規則判斷。
限制：此結果不含跨資料語意分析，建議 API 恢復後重新執行 AI 判讀。
```

## Debug 模式

需要 Debug 模式，但不是 Flask debug。  
這是「AI 判斷追蹤模式」，僅限 admin/superadmin 使用。

Debug 可顯示：

- 判斷來源
- 採證來源
- AI provider
- 模型標籤
- request id
- token 用量
- prompt 摘要
- fallback reason
- Script 耗時與 AI 耗時
- 信心等級
- 遮蔽後證據

Debug 不可顯示：

- 完整 API Key
- 未遮蔽 prompt
- 未遮蔽 IP、hostname、username、password、token、private key、內部 URL

## API Key 管理介面建議

後續應建立 AI / API Key 管理頁：

| 功能 | 說明 |
|---|---|
| Provider | OpenAI、公司內部 LLM、自訂 API Gateway |
| API Key | 只顯示遮蔽值，例如 `sk-********abcd` |
| 測試連線 | 檢查 key、模型、quota、timeout |
| 啟用/停用 | 可一鍵關閉 AI 判斷回到 Script 模式 |
| L1/L2/L3 分流 | 設定不同等級使用 Script、輕量模型或高準確模型 |
| Fallback | 設定 timeout 秒數與接手策略 |
| 使用紀錄 | 誰執行、哪個功能、成功/失敗、耗時與 fallback reason |

## 落地規則

1. 所有 AI 結果都要有 `judgement_source`。
2. 所有 fallback 都要有 `fallback_reason`。
3. UI 不可讓 Script 接手結果看起來像 AI 判斷。
4. 報表匯出也要保留判斷來源。
5. Debug 匯出必須去敏化。
6. L3 可 AI 優先，但不能因 AI API 故障而讓整個維運流程停擺。
