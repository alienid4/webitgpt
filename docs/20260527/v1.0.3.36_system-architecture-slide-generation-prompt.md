# v1.0.3.36 系統架構簡報產生提示語法

日期：2026-05-27  
專案：webitgpt  
用途：讓公司內部 GPT 依照同事範本，產出「開發套件與設計規格、模組化架構、簡易系統架構圖、未來串接方式」。

## 使用方式

把下方提示語法貼給公司內部 GPT，並附上 webitgpt 的交接文件或 repo 摘要。  
若會送到外部 AI，請先移除或遮蔽 IP、hostname、帳號、token、內部網段、部門名稱與真實 URL。

建議搭配文件：

- `docs/20260527/v1.0.3.35_company-gpt-full-development-handoff.md`
- `docs/20260527/v1.0.3.35_company-standard-chapter-by-chapter-compliance.md`
- `docs/20260527/v1.0.3.35_company-standard-compliance-gap-table.md`
- `docs/20260527/v1.0.3.36_ai-judgement-source-ux-design.md`

## 一次產出 HTML 的提示語法

```text
你是一位資深全端工程師、系統架構師與企業簡報顧問。

請根據我提供的系統資料，產出一份單檔 HTML，內容要像企業內部架構簡報，可直接用瀏覽器開啟，也可貼到 PowerPoint 參考。

請嚴格遵守：
1. 使用繁體中文。
2. 不要產生 PHP。
3. 不要假造不存在的功能。
4. 若資料不足，請用「待確認」標示，不要自行編造。
5. IP、hostname、帳號、token、內部 URL 請去敏化，例如 `<IP_MASKED>`、`<HOST_MASKED>`。
6. HTML 必須是單檔，內含 CSS，不依賴外部 CDN。
7. 視覺風格請採企業簡報風：白底、深藍標題、綠色分隔線、表格、圓角資訊框、頁尾。
8. 每個區塊都要適合轉成投影片。

請產出以下內容：

第一頁：專案所使用之開發套件及相關設計規格
- 用表格列出：類別、技術/套件、說明。
- 至少包含：後端框架、Web Server、資料庫、DB Driver、前端框架、前端互動、圖表元件、驗證機制、PDF 報表、API 文件、Session 管理、作業系統/執行環境、部署樣式。

第二頁：模組化架構設計
- 用 4 到 6 個圓角資訊框說明主要模組。
- 每個框包含標題與條列功能。
- 至少包含：資產管理、巡檢/Hardening、帳號盤點、效能月報、核心系統影響圖、系統管理/API。

第三頁：簡易系統架構圖
- 用 HTML/CSS 畫出由上到下的架構圖。
- 至少包含：使用者 Browser、Flask Web Server、MongoDB、外部/匯入資料來源、核心功能模組、報表輸出。
- 右側加上架構說明：系統架構與安全、模組化 Blueprint 架構、後端整合與資料管理、核心功能與報表輸出。

第四頁：未來系統串接及整合方式說明
- 說明未來與 CMDB、IPAM、AD/LDAP、PAM、MSSQL、OpenAPI、監控工具的整合方向。
- 加一個範例表格，欄位包含：來源系統、資料內容、整合方式、狀態、注意事項。

第五頁：資料治理與安全設計
- 說明資料分層、API Key 不進前端、匯入驗證、錯誤列回報、audit log、去敏化、離線部署與備份。
- 加一段「給主管看的結論」，用 3 到 5 點摘要。

第六頁：AI 判斷來源與 fallback 設計
- 以「Shell 負責採證，AI 負責判讀；AI 不可用時，Script 保底接手」為主軸。
- 說明 Script、API Key、AI、AI + Script、Script 接手、證據不足的差異。
- 說明 L1/L2/L3 分流：L1 Script only、L2 輕量 AI 可選、L3 AI 深度判讀。
- 說明 UI 標示：AI 用金框與 AI badge，Script 用灰框，API Key 用綠色 accent，fallback 用 Script 接手 badge。
- 說明 Debug 模式只顯示遮蔽後證據、模型、耗時、request id、fallback reason，不顯示完整 API Key 或未遮蔽 prompt。

最後請只輸出完整 HTML，不要輸出解釋文字。

以下是系統資料，請以此為準：

系統名稱：webitgpt
定位：內部維運與資產治理平台，支援 CMDB 匯入、資產管理、IPAM/nmap 掃描、OS 帳號盤點、AP 帳號盤點匯入、Hardening、NMON 效能月報、核心系統影響圖、API Key 分析可視化、離線安裝。
後端：Python Flask。
後端分層：webapp/app.py、webapp/routes、webapp/services、webapp/templates、webapp/static。
資料庫：目前 MongoDB，未來可規劃 MSSQL + MongoDB 雙資料庫分工。
正式資料建議：CMDB、帳號盤點、審核、稽核可規劃 MSSQL；掃描原始資料、NMON、debug bundle、半結構化匯入暫存可保留 MongoDB。
前端：Jinja templates、vanilla JavaScript、CSS。
報表：PDF/CSV/Excel，效能月報已加入 NMON 圖表與 EOS 摘要。
部署：systemd + gunicorn，離線包支援 RHEL/Rocky，MongoDB 可由 Podman container 提供。
安全：API Key 不放前端，後端代理；正式環境需使用環境變數覆蓋 secret；外部 AI 分析需遮蔽 IP、hostname、帳號、token、內部 URL。
AI 判斷原則：Shell 負責採證，AI 負責判讀；AI 不可用時，Script 保底接手。
AI 判斷來源 UI：Script 判斷用灰框，API Key 驗證用綠色 accent，AI 判斷用金框與 AI badge，AI + Script 表示採證與判讀分離，Script 接手表示 AI API timeout/error 後保守降級。
L1/L2/L3：L1 基礎檢查使用 Script only；L2 一般判讀可使用輕量 AI；L3 深度檢查使用 AI 綜合 CMDB、nmap、NMON、帳號、log、拓撲等證據判讀，失敗時 Script 接手。
測試流程：先在 221 測試主機驗證，再推 GitHub Release；224 用於離線移植測試。
目前版本：v1.0.3.36。
```

## 產出 PowerPoint 的提示語法

如果公司 GPT 支援直接產 PPT，可改用這段：

```text
你是一位企業架構簡報顧問。請根據下方系統資料，產出 5 頁 PowerPoint 大綱與每頁可直接貼到投影片的內容。

風格請接近企業內部審查簡報：
- 白底
- 深藍標題
- 綠色橫線
- 表格與圓角資訊框
- 每頁頁尾顯示系統名稱與版本

請產出：
1. 專案所使用之開發套件及相關設計規格
2. 模組化架構設計
3. 簡易系統架構圖
4. 未來系統串接及整合方式說明
5. 資料治理與安全設計
6. AI 判斷來源與 fallback 設計

請不要假造不存在的功能；不足處標示「待確認」。請遮蔽 IP、hostname、帳號、token 與內部 URL。

以下是系統資料：
<貼上 webitgpt 系統資料或交接文件摘要>
```

## 產出 Mermaid 架構圖的提示語法

```text
請根據 webitgpt 系統資料產生 Mermaid flowchart。

要求：
1. 使用 top-down 架構。
2. 節點包含 Browser、Flask Web Server、Routes、Services、MongoDB、Import Sources、Reports、External Integrations。
3. 標籤使用繁體中文。
4. 不顯示真實 IP、hostname 或內部 URL。
5. 只輸出 Mermaid code block。
```
