## Known User-Reported Symptoms

### CSV import appears stuck

Likely causes:

- Browser is rendering a large raw error list from a failed import.
- CSV has many invalid rows.
- File is over 2000 rows and should be split.
- MongoDB is unavailable or slow.
- `market_hours_protection` blocks admin writes during market hours for admin users.

Current expected v1.0.3.35 behavior:

- Bad CSV should return quickly with a concise summary.
- Only first 10 errors show in UI.
- Page should show `耗時`.
- Over 2000 rows should show a human-readable split-file message.

### RHEL 9.6 migration / Podman / Mongo issue

Historical issue:

- A previous offline bundle included Rocky/RHEL 9.7 RPMs on RHEL 9.6.
- Installing those caused protected package and release package conflicts.
- The correct behavior is to use native RHEL 9.6 repositories or RHEL 9.6-compatible RPMs, and never install Rocky release packages on RHEL.

## First-Line Diagnostic Commands

Run on the webitgpt host.

```bash
date
systemctl is-active webitgpt
curl -fsS http://127.0.0.1:8002/health
curl -fsS http://127.0.0.1:8002/ready
ss -ltnp | grep -E '8002|27017' || true
```

Expected:

- `webitgpt` is `active`.
- `/health` returns `version=1.0.3.35`.
- `/health` returns `patch_id=cmdb-import-fast-feedback`.
- Port `8002` is listening.
- MongoDB port `27017` is listening locally.

## Log Collection Commands

```bash
journalctl -u webitgpt -n 160 --no-pager
tail -n 200 /opt/webitgpt/logs/error.log
tail -n 200 /opt/webitgpt/logs/access.log
```

Look for:

- Gunicorn worker timeout.
- Python traceback.
- HTTP 500 for `/hosts/import/csv`.
- Very long request time around the user's import time.
- MongoDB connection refused.

## Mongo / CMDB Count Check

```bash
cd /opt/webitgpt
/opt/webitgpt/venv/bin/python - <<'PY'
from webapp.services.mongo_service import get_collection

for name in [
    "hosts",
    "ip_reservations",
    "network_scan_reports",
    "host_lifecycle_events",
    "host_identity_checks",
    "asset_identity_refresh_runs",
    "audit_logs",
]:
    try:
        print(name, get_collection(name).count_documents({}))
    except Exception as exc:
        print(name, "ERR", exc)
PY
```

If `hosts` is unexpectedly huge, check whether the user imported the same file repeatedly or imported test rows.

## CSV Import Fast Reproduction

This command intentionally sends bad rows to verify that v1.0.3.35 returns quickly and does not render a huge raw error blob.

```bash
cd /opt/webitgpt
/opt/webitgpt/venv/bin/python - <<'PY'
from pathlib import Path
import subprocess

rows = ["資產序號,資產狀態,資產名稱,主機名稱,IP,完整性(I),機密性(C),可用性(A)"]
for i in range(1, 81):
    rows.append(f"BAD-{i},使用中,壞資料{i},,not-ip,xxx,3,3")

path = Path("/tmp/bad_import_10335.csv")
path.write_text("\n".join(rows), encoding="utf-8")

cmd = [
    "curl",
    "-sS",
    "-m",
    "30",
    "-w",
    "\nHTTP:%{http_code} TIME:%{time_total}\n",
    "-F",
    f"csv_file=@{path};type=text/csv",
    "http://127.0.0.1:8002/hosts/import/csv",
]
text = subprocess.check_output(cmd).decode("utf-8", "replace")
print(text[-800:])
print("summary_present", "CMDB 匯入結果摘要" in text)
print("first10_notice", "錯誤明細只顯示前 10 筆" in text)
print("elapsed_present", "耗時" in text)
print("raw_error_blob_suspected", text.count("BAD-") > 20)
PY
```

Expected:

- `HTTP:400`
- Short elapsed time, normally under 1 second on 221.
- `summary_present True`
- `first10_notice True`
- `elapsed_present True`
- `raw_error_blob_suspected False`

- Row count.

- Screenshot cropped to the webitgpt page only.
- Outputs from:
