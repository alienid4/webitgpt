專案所使用之開發套件及相關設計規格

webitgpt 為 Flask 核心的內部維運與資產治理平台，支援資產管理、巡檢、帳號盤點、效能月報、核心系統影響圖與離線部署。

類別技術 / 套件說明
後端框架Flask / PythonWeb API 與後台管理系統核心。
Web ServerGunicorn + systemd正式部署以 systemd 管理服務，Gunicorn 提供 WSGI runtime。
資料庫MongoDB儲存資產、掃描、帳號盤點、報表與半結構化資料。
ORM / DB DriverPyMongoPython 與 MongoDB 整合。
前端框架Jinja Templates / HTML / CSS伺服器端渲染管理頁面，保留低複雜度。
前端互動Vanilla JavaScript處理局部互動、表單提示、匯入回饋與視覺化控制。
圖表元件Chart.js / HTML SVGDashboard、NMON 月報、拓撲與影響圖視覺化。
驗證機制LDAP / Active Directory、Session整合企業帳號登入與管理 session。
PDF / 匯出ReportLab、CSV、Excel產出 Hardening、效能月報、CMDB 匯出與差異報告。
API 文件flask-smorest / OpenAPI 規劃中目前尚未全 API 覆蓋，建議從 CMDB、hosts、API Key verify 補強。
部署樣式Offline installer / Podman MongoDB支援 RHEL/Rocky 離線移植；MongoDB 可由 Podman container 提供。

未來系統串接及整合方式說明

webitgpt 後續可逐步從匯入式治理，擴充為 API / DB / 目錄服務整合平台。正式整合前應先完成 OpenAPI、資料分級、權限與 audit log 設計。

來源系統資料內容整合方式狀態注意事項
CMDB資產主檔、主機、IP、owner、CIA、備份資訊CSV / Excel 匯入，未來可 API 或 MSSQL view已支援匯入需欄位治理與錯誤列回報。
IPAM / nmap網段、保留 IP、未納管 IP、開放 portnmap 掃描與系統對帳已支援掃描範圍需授權，避免誤掃。
AD / LDAP使用者登入、群組、部門資訊後端驗證與角色映射可整合正式環境需 session timeout 與權限稽核。
PAM特權帳號、保管狀態、權限歸屬CSV / Excel 或 API規劃中不可在前端保存密碼或 token。
MSSQL正式主檔、審核、稽核與治理資料Repository / service layer設計中不建議直接取代 MongoDB，需 migration design。
OpenAPIAPI 文件、外部系統串接契約flask-smorest / `/api-docs`待補強先從 CMDB、hosts、API Key verify API 補。
監控工具NMON、EOS、主機健康、效能趨勢匯入、排程採集、報表產出部分支援採集需 timeout、限流與執行紀錄。

資料治理與安全設計

資料分層正式主檔與稽核資料可規劃 MSSQL；掃描原始資料、NMON、debug bundle 與半結構化暫存保留 MongoDB。
匯入治理CMDB 與 AP 帳號匯入需提供欄位檢核、錯誤列回報、草稿區與正式資料更新流程。
API Key 安全API Key 不放前端，由後端代理判斷，UI 應明確標示「API 分析」來源。
治理項目目前做法後續強化
機敏資訊debug 與交接文件要求遮蔽 IP、hostname、帳號、token。匯出與 log 預設增加 masking 規則。
錯誤回報CMDB 匯入已改為摘要、前 10 筆錯誤與耗時顯示。提供錯誤列下載與欄位修正建議。
權限與稽核已有管理模組與 session 機制。寫入型功能前補 audit log、角色、rollback。
離線部署支援 RHEL/Rocky 離線安裝與 patch package。強化一鍵安裝、MongoDB/Podman 檢查、MSSQL 選項。
測試與發布先在 221 測試，確認後推 GitHub Release。重大 UI 加瀏覽器截圖驗證，API 加 OpenAPI regression。

給主管看的結論

  • webitgpt 已具備資產、巡檢、帳號、報表與影響分析的核心雛形。
  • 短期最有價值是補 OpenAPI、MSSQL migration design、匯入治理與 audit log。
  • 不建議為了形式合規立刻重寫 Node.js 或把 MongoDB 全面改成 MSSQL。
  • 後續採「新功能先合規，舊功能漸進補強」最安全。

AI 判斷來源與 Fallback 設計

亮點原則：Shell 負責採證，AI 負責判讀；AI 不可用時，Script 保底接手。使用者必須一眼看出每個結果是 AI、Script、API Key 或 fallback 產生。

Script 判斷

L1 基礎檢查

服務是否啟動、port 是否開、版本是否一致、磁碟或 CPU 門檻等固定規則，由 shell/script 採證與判斷。

API Key 驗證

正式 API 權限判斷

使用 Bearer token 呼叫後端 API，確認版本、Mongo、資料品質與 API 狀態，UI 以綠色 accent 標示。

AI 判斷

L3 深度檢查

AI 綜合 CMDB、nmap、NMON、帳號盤點、log 與拓撲資料，判斷風險、可能原因、影響範圍與下一步。

AI + Script

採證與判讀分離

Script 提供可追溯證據，AI 只負責語意判讀；報表保留證據來源、信心等級、模型標籤與耗時。

Script 接手

AI 不可用時保底

當 API key invalid、timeout、quota、provider error 時，自動降級為 script rule，並清楚顯示 fallback reason。

Debug 模式

可追蹤但要去敏

admin 可查看 provider、model、request id、耗時、prompt 摘要與遮蔽證據；不顯示完整 key 或未遮蔽內部資料。

等級預設策略AI 可用時AI 不可用時
L1Script only通常不需要 AIScript 照常執行
L2Script + 輕量 AI 可選摘要、分類、簡單異常解釋Script rule 接手
L3Script 採證 + AI 深度判讀跨資料根因與風險判斷Script 保底接手並標示限制
