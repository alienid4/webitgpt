# v1.0.3.35 Company Standard Compliance Gap Table

Date: 2026-05-27

Purpose: explain to the company which parts of the company structured development standard webitgpt already follows, which parts are partially aligned, and which parts cannot be forced immediately without architecture risk.

## Executive Summary

webitgpt is not a greenfield template project. It is an existing Flask + MongoDB + systemd + offline-install operations platform with field deployments and release history.

The company standard is valid as the target direction for new development. However, applying every rule immediately would create unnecessary risk, especially in these areas:

- MongoDB vs company default SQL Server
- existing API response formats vs mandatory `{ ok, data/error }`
- incomplete OpenAPI coverage
- existing Flask project layout vs company sample layout
- existing Jinja templates and page JS vs strict frontend separation

Recommended position:

> New functions should follow the company standard. Existing functions should remain compatible and migrate gradually with tests, 221 validation, and release notes.

## Compliance Table

| 規範項目 | webitgpt 現況 | 符合狀態 | 執行問題 / 說明 | 建議做法 |
|---|---|---|---|---|

## Why Full Immediate Compliance Is Risky

| 立即硬套項目 | 風險 |
|---|---|
| MongoDB 直接改 SQL Server | 需要重新設計 collections、query、index、migration、transaction、installer，容易造成資料遺失或功能回歸 |
| 所有 API 一次改 `{ ok, data/error }` | 前端 fetch、curl 腳本、測試、post-install verify、第三方使用者可能全部受影響 |
| 專案目錄搬成公司範本 | import path、systemd 啟動、offline patch、測試與部署腳本都要重驗 |
| 所有 API 一次補 Swagger | 工作量大且容易卡住當前 field fix 節奏 |
| 一次拆所有 Jinja/JS | 高風險低收益，容易造成 UI regressions |

## Recommended Compliance Roadmap

| 優先級 | 項目 | 做法 |
|---|---|---|
| P0 | 禁止 PHP、secrets、前端 API key | 立即持續遵守 |
| P0 | 221 先測再 release | 立即持續遵守 |
| P1 | OpenAPI 補強 | 從 `/api/v1`、CMDB import/export、hosts APIs 開始 |
| P1 | API response 標準化 | 只對新 API 採 `{ ok, data/error }`，舊 API 保相容 |
| P1 | MSSQL 遷移 | 先做 migration design 和 repository boundary，不直接改 |
| P2 | 前端 inline handler 清理 | touched area 漸進移到 JS |
| P2 | 大型 template/route 拆分 | 隨功能修改逐步拆，不做大爆炸重構 |

## Company-Facing Explanation

webitgpt 已符合公司規範的核心精神：不用 PHP、前後端分層、機密不放前端、後端處理 API、具備測試與 release 文件。

不完全符合的地方主要來自既有架構，而不是開發失控。例如公司正式資料庫預設 SQL Server，但 webitgpt 已經是 MongoDB 架構並完成部署、離線移植與多版 patch。若立刻改成 SQL Server，會是資料層大遷移，不是一般 refactor。

因此建議公司接受「漸進式合規」：新功能遵守公司規範；舊功能在不破壞部署與使用者流程的前提下，逐步補 OpenAPI、統一 response wrapper、拆分 route/template，並另案規劃 MSSQL migration。
