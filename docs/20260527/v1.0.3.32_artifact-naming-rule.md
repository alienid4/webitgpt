# Artifact Naming Rule

Field-facing release files, patch files, and copy-from-GitHub documents must
be grouped by date directory. File names inside the date directory must start
with the version, then the function.

## Required Format

```text
YYYYMMDD/v1.0.X.Y_function-name.ext
```

## Examples

```text
20260527/v1.0.3.32_rhel96-installer-hotfix-patch.tar.gz
20260527/v1.0.3.32_rhel96-field-commands.md
20260527/v1.0.3.32_field-issue-intake-and-masking.md
```

## Rules

- The filename must begin with the version.
- The parent directory must be the date in `YYYYMMDD` format.
- The function name must follow the version.
- Use hyphens inside the function name.
- Do not put project name, package type, or free text before the version.
- For release assets, keep the timestamp suffix only when multiple builds may
  exist on the same date.

## Not Allowed

```text
webitgpt_v1.0.3.32_rhel96-installer-hotfix-patch.tar.gz
rhel96-installer-hotfix-patch_v1.0.3.32.tar.gz
field_issue_intake_and_masking.md
v1.0.3.32_20260527_rhel96-field-commands.md
```
