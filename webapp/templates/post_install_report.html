安裝後驗證

離線移植後不要只看服務有沒有啟動；這裡把「API Key 驗證」與「Script 檢查」分開，讓使用者一眼看出判斷來源。

健康檢查 資料品質
API Key 驗證

正式 API 權限判斷

使用 Bearer token 呼叫 /api/v1/post-install/verify，由 API 回傳版本、Mongo 與資料品質 API 狀態。

必要 scope
system:read
回應標記
verification_source=api_key
適用情境
外部監控、船上移植驗收、系統對系統檢查
Script 檢查

本機 curl 腳本檢查

不帶 API_TOKEN 時只檢查公開 health、ready、頁面與資料品質 API 是否可連線。

必要條件
能在主機上執行 script
回應標記
沒有 API Key 身分證明
適用情境
初裝後快速自檢、服務啟動確認

建議驗證指令

Script 檢查 沒有 API Key，適合先確認服務能不能打開。 
EXPECTED_VERSION={{ app_version }} BASE_URL=http://127.0.0.1:8002 bash scripts/post_install_verify.sh
API Key 驗證 請先在「系統管理 / API Token」核發含 system:read scope 的 token。 
EXPECTED_VERSION={{ app_version }} API_TOKEN=wgpt_xxx BASE_URL=http://127.0.0.1:8002 bash scripts/post_install_verify.sh
curl -H "Authorization: Bearer wgpt_xxx" "http://127.0.0.1:8002/api/v1/post-install/verify?expected_version={{ app_version }}"
